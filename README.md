# DualVPN

Два туннеля WireGuard одновременно: рабочий и личный. Трафик рабочей сети идёт
в один, весь остальной — в другой. Корпоративные ресурсы доступны, не отключая
личный VPN, и наоборот.

Приложение для macOS: значок в меню-баре и окно с состоянием, конфигами и
живым логом. Под капотом [sing-box](https://sing-box.sagernet.org).

## Зачем

Обычный клиент WireGuard держит одно соединение. Если рабочий конфиг
прописывает `AllowedIPs = 0.0.0.0/0`, он забирает весь трафик, и личный VPN
включить уже нельзя. Если наоборот — недоступна рабочая сеть.

Здесь подняты оба туннеля, и для каждого пакета решается, куда его отправить:

1. адрес попадает в подсети рабочего конфига → рабочий туннель
2. адрес локальный (`10/8`, `192.168/16`) → мимо туннелей, в свою сеть
3. всё остальное → личный туннель

Домены рабочей сети резолвит корпоративный DNS, остальные — публичный через
личный туннель.

## Что нужно

* macOS 13 или новее (проверено на 26.6, Apple Silicon)
* Python 3.9+ — есть в системе
* бинарник sing-box — качается отдельно, см. ниже
* конфиги WireGuard: рабочий и личный

## Установка: готовое приложение

Скачай `DualVPN-<версия>.dmg` из
[релизов](https://github.com/sotakeiteasy/dual-vpn/releases), перетащи
`DualVPN.app` в «Программы».

Приложение **не подписано** — Apple берёт за это 99 $ в год. Поэтому первый
запуск: правой кнопкой по нему → «Открыть» → «Открыть» ещё раз. Дальше
открывается обычно.

Дальше в окне:

1. **«Установить службу…»** — спросит пароль администратора. Туннель правит
   таблицу маршрутов, без прав это невозможно; окно работает от обычного
   пользователя и само туннелем не управляет.
2. **«Добавить конфиг…»** — положи рабочий и личный `.conf`.
3. **«Настроить рабочую сеть…»** — домены, которые должен резолвить
   корпоративный DNS, и хост для проверки связи. Можно заполнить поля, а можно
   нажать «Взять из файла…» и подсунуть готовый `site.env`. Без этого туннели
   работают, но имена рабочей сети не резолвятся.
4. **«Включить»**.

Всё нужное лежит внутри `.app`, включая sing-box. Конфиги и состояние —
в `~/Library/Application Support/DualVPN`, поэтому обновление приложения их
не трогает.

Удалить: перетащи `.app` в корзину и выполни
`sudo launchctl bootout system/local.singbox-lx`, затем удали
`/Library/LaunchDaemons/local.singbox-lx.plist` и `/etc/sudoers.d/singbox-lx`.

## Установка из исходников

```bash
git clone git@github.com:sotakeiteasy/dual-vpn.git
cd dual-vpn
```

**1. Скачай бинарник sing-box** в `lib/bin/`.

Нужен форк [Leadaxe/sing-box-lx](https://github.com/Leadaxe/sing-box-lx) —
в основной сборке нет AmneziaWG, а без него личный конфиг с полями `Jc`, `S1`,
`H1` не поднимется. Из Homebrew тоже не годится: там сборка без него.

```bash
mkdir -p lib/bin && cd lib/bin

VER=1.14.0-lx.22
ARCH=darwin-arm64          # для Intel: darwin-amd64
BASE=https://github.com/Leadaxe/sing-box-lx/releases/download/v$VER

curl -L --progress-bar -O $BASE/sing-box-$VER-$ARCH.tar.gz
curl -sSL -O $BASE/SHA256SUMS

# суммы должны совпасть
grep $ARCH SHA256SUMS && shasum -a 256 sing-box-$VER-$ARCH.tar.gz

tar xzf sing-box-$VER-$ARCH.tar.gz --strip-components=1 -C . \
    sing-box-$VER-$ARCH/sing-box
chmod +x sing-box && xattr -dr com.apple.quarantine sing-box
./sing-box version         # в строке Tags должно быть with_awg
rm -f sing-box-$VER-$ARCH.tar.gz SHA256SUMS
cd ../..
```

Если личный сервер обычный WireGuard, без маскировки, подойдёт и основная
сборка sing-box — но проверено на этой.

**2. Положи конфиги** в `conf/`. Тип определяется именем файла:

| | имена | формат |
|---|---|---|
| рабочий | `corp.conf`, `wg.conf`, `wg-*.conf`, `wg0-*.conf` | обычный WireGuard |
| личный | `personal.conf`, `awg-*.conf`, `amnezia-*.conf` | WireGuard или AmneziaWG |

Образцы — в `conf/*.example`. Рабочий должен быть ровно один; личных сколько
угодно, переключаются в окне.

Важно: у рабочего конфига **не должно быть** `AllowedIPs = 0.0.0.0/0` —
маршруты рабочего туннеля берутся именно оттуда, и `0.0.0.0/0` заберёт весь
трафик.

**3. Опиши свою рабочую сеть** — скопируй `conf/site.env.example` в
`conf/site.env` и укажи домены. То же самое делает кнопка «Настроить рабочую
сеть…» в окне. Без этого туннели работают, но имена рабочей сети не
резолвятся.

**4. Поставь приложение:**

```bash
bash install.sh
```

Скрипт создаст окружение, соберёт `.app`, прогонит проверки и только потом
тронет систему. Запускать без `sudo` — пароль он спросит сам, один раз.

Соберётся `.app`, встанет служба launchd, появится `/Applications/DualVPN.app`.
Автозапуска при загрузке нет — только по кнопке.

Приложение не подписано, поэтому первый запуск: правой кнопкой → «Открыть» →
«Открыть». Дальше открывается обычно.

Удалить всё: `bash install.sh remove`.

### Обновление и переустановка

`install.sh` можно запускать сколько угодно: он пересобирает приложение,
переставляет службу и при провале проверок ничего не меняет.

```bash
git pull && bash install.sh
```

Всё, что не под гитом — конфиги, `conf/site.env`, бинарник, `lib/state/` —
живёт в той же папке и переустановку переживает.

## Как пользоваться

Значок в меню-баре показывает состояние и включает туннели. «Открыть окно…»
даёт полную картину:

* **Состояние** — четыре положения: всё работает · рабочая сеть не отвечает ·
  выключено · трафик мимо туннеля
* **Конфиги** — добавить, посмотреть, отредактировать, удалить; переключение
  личного профиля. Правятся только при выключенном VPN
* **Логи** — живые, с поиском и фильтром по ошибкам
* **Как это работает** — объяснение на твоём собственном конфиге

Всё то же самое доступно из терминала:

```bash
sudo ./vpn ui        # панель в терминале вместо приложения
sudo ./vpn start     # поднять туннели
sudo ./vpn stop      # опустить и откатить маршруты
sudo ./vpn status    # что сейчас поднято
sudo ./vpn diag      # полная диагностика
./vpn list           # какие конфиги видны
./vpn version        # версия программы и sing-box
```

Версия лежит в файле `VERSION` в корне — оттуда её берут и окно, и сборка
`.app`, чтобы номера не разъезжались. В окне она внизу левой колонки, рядом
с версией sing-box.

## Устройство

```
vpn                     всё управление: сборка конфига, маршруты, откат
conf/                   конфиги WireGuard и настройки сети (не в репозитории)
lib/bin/sing-box        бинарник (не в репозитории)
lib/scripts/
  build-config.py       .conf → config.json для sing-box
  menubar.py            приложение: значок в меню-баре
  window.py             окно на WKWebView
  ui/index.html         вёрстка окна
  tui.py                панель в терминале, общий пробер состояния
  selftest.sh           проверки
lib/launchd/            описание фоновой службы
windows/                вариант для Windows, со своим README
lib/state/              собранный конфиг, логи, состояние (не в репозитории)
```

**Почему две программы.** Туннель правит таблицу маршрутов, а на это нужны
права root. Поэтому им владеет служба launchd, а приложение работает от
обычного пользователя: показывает состояние и посылает службе две команды.
Права выданы точечно, через `/etc/sudoers.d`, ровно на запуск и остановку
этой службы.

## Известные особенности

**MTU.** Если в конфиге нет строки `MTU`, подставляется 1280 — значение,
работающее везде. Клиент WireGuard в этой ситуации поступает так же. С 1420
некоторые серверы завершают рукопожатие, но не пропускают данные: туннель
выглядит поднятым, а интернета нет.

**Сон.** Пока Mac спит, соединение рвётся, и открытые до сна страницы остаются
висеть на мёртвых соединениях — это свойство TCP, восстановление туннеля их не
воскрешает. Пока туннель поднят, программа удерживает систему от засыпания по
простою (`caffeinate -i`). Закрытие крышки этим не покрывается.

**Проверка утечки.** Перед подъёмом туннеля запоминается настоящий адрес от
провайдера; утечкой считается только совпадение с ним. Сравнение с адресом
сервера ненадёжно: сервер может выходить в сеть не тем адресом, на котором
принимает соединения.

## Сборка релиза

```bash
bash lib/scripts/make-dmg.sh       # dist/DualVPN-<версия>.dmg
```

Скрипт сам пересобирает приложение и прогоняет проверки: `install.sh` образ
не трогает, и без этого в DMG легко уехала бы вчерашняя сборка.

Номер берётся из файла `VERSION`.

## Проверки

```bash
bash lib/scripts/selftest.sh
```

Синтаксис, кодировки, ротация логов, валидность plist, а для собранного
приложения — целостность подписи, запуск, отсутствие исключений в JS и то, что
каждая часть окна отработала. `install.sh` прогоняет их сам и при провале
ничего не устанавливает.
