# DualVPN

Два туннеля WireGuard одновременно: рабочий и личный. Подсети рабочего конфига
идут в один туннель, всё остальное — в другой. Под капотом
[sing-box](https://sing-box.sagernet.org) (форк [sing-box-lx](https://github.com/Leadaxe/sing-box-lx) с поддержкой AmneziaWG).

Приложение для Windows: служба держит туннель и правит маршруты, значок в
трее — включает и выключает, окно показывает состояние, конфиги и живой лог.

> **Статус: собирается, но не обкатано.** Написано всё: служба, трей, окно,
> установщик. Проверено пока только сборкой и статическим разбором — живого
> прогона на Windows ещё не было, так что считай это рабочей бетой.

## Как разводится трафик

Правила проверяются по порядку, до первого совпадения:

1. адрес в подсетях рабочего конфига (`AllowedIPs`) → рабочий туннель
2. адрес локальный (`10/8`, `172.16/12`, `192.168/16`) → мимо туннелей
3. остальное → личный туннель

Домены рабочей сети резолвит корпоративный DNS через правила sing-box —
запросы идут прямо через tun, отдельная настройка системы не нужна.

## Устройство

```
lib/dualvpn/
  paths.py          где что лежит: код, данные, бинарники
  winnet.py         маршруты, интерфейсы, IPv6, DNS — через PowerShell
  buildconfig.py    .conf → config.json для sing-box
  tunnel.py         подъём/остановка, журнал владения маршрутами, откат
  probe.py          пробер состояния: что поднято, есть ли утечка
  ipc.py            именованный канал между службой и треем
  service.py        служба Windows: сводит всё вместе
  portable.py       версия без установки: то же ядро, но в своём процессе
  tray.py           значок в трее
  window.py         окно на WebView2, мост к вёрстке
  cli.py            консольное управление (dualvpn start/stop/status/...)
  ui/index.html     вёрстка окна
installer/
  dualvpn.spec      PyInstaller: два exe, одна общая папка
  dualvpn.iss       Inno Setup: служба, права на данные, ярлыки
  build.ps1         сборка целиком, от окружения до установщика
conf/               .conf-файлы и site.env, вне гита
```

Туннель правит таблицу маршрутов, поэтому им владеет служба под LocalSystem,
а трей и окно работают от обычного пользователя и шлют ей команды через
именованный канал. UAC спрашивают один раз при установке службы, а не на
каждое включение.

**Чужое не трогаем.** Половинки дефолтного маршрута (`0.0.0.0/1`,
`128.0.0.0/1`) — общий ресурс: ровно их же ставят себе Amnezia, официальный
клиент WireGuard и любой другой VPN. Каждое снятие маршрута сначала проверяет
владельца по журналу и по факту, что интерфейс — наш, и только потом снимает
строку.

## Как запускать

Три способа, от простого к полному.

**Портативно — один файл.** `DualVPN-Portable.exe`: ни установки, ни службы.
Двойной клик, один раз UAC — и значок в трее. Внутри уже всё, включая sing-box
и wintun. Конфиги и состояние кладутся в `DualVPN-Data\` рядом с exe, так что
папку можно унести целиком.

Отличие одно: туннель держит сам процесс, поэтому «Выход» из трея его
опускает и возвращает маршруты. В установленной версии этим занимается служба,
и закрытие значка VPN не выключает.

**Установка.** `DualVPN-<версия>-setup.exe` ставит службу, ярлыки и автозапуск.
Служба переживает выход из системы и перезагрузку, UAC спрашивается один раз —
при установке.

**Из исходников** — для разработки, см. ниже.

Готовых `.exe` в репозитории нет: их собирает `installer\build.ps1` на
Windows-машине (раздел «Сборка»).

## Из исходников

Нужны Windows 10/11, Python 3.9+, права администратора и два бинарника рядом
в `lib/bin\`:

* [`sing-box-lx`](https://github.com/Leadaxe/sing-box-lx/releases) —
  `sing-box-<версия>-windows-amd64.zip`, форк с AmneziaWG;
* `wintun.dll` — [wintun.net](https://www.wintun.net/), тот же файл, что несёт
  официальный клиент WireGuard.

```powershell
git clone https://github.com/enkeym/dual-vpn.git
cd dual-vpn

python -m venv lib\venv
lib\venv\Scripts\pip install -r requirements.txt

copy \путь\к\personal.conf conf\
copy \путь\к\wg0-corp.conf conf\

set DUALVPN_DATA=%cd%
lib\venv\Scripts\python -m dualvpn.cli service console
```

`service console` запускает логику службы прямо в консоли, без установки —
удобно для разработки: трей (`python -m dualvpn.cli tray`) и окно подключатся
к ней так же, как к настоящей службе.

## Сборка установщика

```powershell
powershell -ExecutionPolicy Bypass -File installer\build.ps1
```

Скрипт сам создаёт окружение, ставит зависимости, рисует значок и собирает:

* `dist\DualVPN-Portable.exe` — портативная версия, один файл;
* `dist\DualVPN\` — установочная пара `DualVPN.exe` (трей) и `dualvpn.exe`
  (CLI и служба);
* `installer\Output\DualVPN-<версия>-setup.exe` — если найден
  [Inno Setup](https://jrsoftware.org/isdl.php). Без него сборка
  останавливается на готовых exe.

Установщик заводит `C:\ProgramData\DualVPN` с раздельными правами (`conf\` —
только SYSTEM и администраторы, там приватные ключи; `state\` — пользователям
на чтение, оттуда трей берёт состояние), ставит службу на автозапуск и вешает
ей перезапуск при падении. Удаление снимает туннель и службу, но конфиги
оставляет.

## Конфиги

Тип определяется именем файла:

| | имена | формат |
|---|---|---|
| рабочий | `corp.conf`, `wg.conf`, `wg-*.conf`, `wg0-*.conf` | WireGuard |
| личный | `personal.conf`, `awg-*.conf`, `amnezia-*.conf` | WireGuard или AmneziaWG |

Рабочий должен быть ровно один, личных сколько угодно — переключаются
профилем (`dualvpn profile <имя>`). У рабочего не должно быть
`AllowedIPs = 0.0.0.0/0`: маршруты берутся оттуда, и он заберёт весь трафик.
Образцы — в `conf/*.example`.

Домены рабочей сети задаются в `conf/site.env` (см. `site.env.example`).

## Из консоли

```
dualvpn status              что сейчас поднято
dualvpn start [ПРОФИЛЬ]     поднять
dualvpn stop                опустить и откатить маршруты
dualvpn list                какие конфиги видны
dualvpn profile ИМЯ         выбрать личный конфиг по умолчанию
dualvpn log [N]             последние строки журнала sing-box
dualvpn version

dualvpn service install     поставить и запустить службу (от администратора)
dualvpn service remove
dualvpn service start|stop|restart
```

## Особенности

**MTU.** Если в конфиге нет строки `MTU`, подставляется 1280. С 1420 часть
серверов завершает рукопожатие, но не пропускает данные — туннель выглядит
поднятым, а интернета нет.

**Сон.** Пока туннель поднят, служба держит `SetThreadExecutionState`, чтобы
система не засыпала по простою. После сна открытые до него соединения мертвы —
восстановление туннеля их не воскрешает.

**IPv6.** Личный сервер v6-адрес не выдаёт, нести v6 в туннель нечем.
На время работы туннеля исходящий IPv6 блокируется правилом брандмауэра и
снимается при выключении — обратимо и мгновенно, в отличие от отключения
адаптера.

**Утечка.** Перед подъёмом туннеля запоминается адрес провайдера, утечкой
считается совпадение с ним. Сравнивать с адресом сервера ненадёжно: он может
выходить не тем адресом, на котором принимает соединения.

## Тесты

```bash
pip install pytest
python -m pytest tests -q
```

Гоняются в CI на каждый push. Покрывают чистую логику: разбор `.conf`,
границы прав на канале, чтение и запись `site.env` и — главное — владение
маршрутами: половинки дефолта общие с другими VPN-клиентами, и ошибка там
означает оторванную сеть у соседнего туннеля, а не своё «не работает».

Чего они не проверяют: поведение самой Windows — именованные каналы,
PowerShell, службы, wintun, сборку PyInstaller. Всё это живёт только на
настоящей машине, и найденные до сих пор ошибки были именно там.
